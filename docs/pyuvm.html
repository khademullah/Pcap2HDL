Separate path · make pyuvm

pcap into nic_rx through UVM classes

This page is a separate UVM-class path on the same nic_rx pins: sequences and the scoreboard live in Python (pyuvm + cocotb), so you can practice a standard agent stack and handshake checks without changing the DPI-C main gate. make pyuvm opens a capture with the same dpi/pcap_reader.c libpcap path, then a pyuvm AXIS agent drives nic_rx. The scoreboard checks that streamed frames, tlast handshakes, and irq_rx pulses match. Default make (DPI-C master under tb_pcap_dpi) stays the main gate.

Data path

make pyuvm MAX_PACKETS=8 is this pipeline: pcap bytes → UVM sequence → AXIS driver → nic_rx, with a monitor and scoreboard on the same bus.

UVM layout

Same run as a classic agent stack: test → env → agent (sequencer, driver, monitor) and a scoreboard.

Commands

One-time venv, then only make pyuvm:

python3 -m venv /tmp/pcap2hdl-pyuvm
/tmp/pcap2hdl-pyuvm/bin/pip install 'cocotb==1.9.2' pyuvm
make pyuvm MAX_PACKETS=8
make pyuvm FILTER='tcp' MAX_PACKETS=8
make pyuvm PCAP=ci.pcap MAX_PACKETS=8
CommandWhat it streams
make pyuvm MAX_PACKETS=8 First 8 frames of traffic.pcap (any EtherType) into nic_rx
make pyuvm FILTER='tcp' MAX_PACKETS=8 Eight TCP frames from traffic.pcap into nic_rx
make pyuvm PCAP=ci.pcap MAX_PACKETS=8 CI synthetic pcap (seven frames if the file ends first)

Shared knobs with the DPI-C bench: PCAP, MAX_PACKETS, FILTER. Missing PCAP writes ci.pcap via scripts/gen_pcap.py.
